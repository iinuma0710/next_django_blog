# Django の認証機能の改修 その２
前回は、Django がデフォルトで提供している User モデルを、自分で定義した CustomUser モデルに切り替えました。
今回は、JWT 認証でユーザ権限なども含めて取得できるように変更します。

## シリアライザのカスタマイズ
```djangorestframework-simplejwt``` を使って発行されるトークンには、デフォルトでユーザの権限情報などは含まれていません。
しかし、Next.js 側でユーザ ID や権限周りの情報を利用したいので、シリアライザをカスタマイズして、それらの情報も含めてトークンを発行するように変更します。

```backend/account/serializers.py```
```python
from rest_framework_simplejwt.serializers import TokenObtainPairSerializer, TokenRefreshSerializer
from rest_framework_simplejwt.tokens import RefreshToken, AccessToken
from rest_framework_simplejwt.exceptions import InvalidToken
from django.contrib.auth import get_user_model

User = get_user_model()

class CustomTokenObtainPairSerializer(TokenObtainPairSerializer):
    @classmethod
    def get_token(cls, user):
        token = super().get_token(user)

        # Token に追加の情報を埋め込む
        token['user_id'] = user.id
        token['is_staff'] = user.is_staff
        token['is_superuser'] = user.is_superuser

        return token
    
class CustomTokenRefreshSerializer(TokenRefreshSerializer):
    def validate(self, attrs):
        data = super().validate(attrs)

        # トークンからユーザを取得
        refresh = RefreshToken(attrs['refresh'])
        user_id = refresh['user_id']

        try:
            user = User.objects.get(id=user_id)
        except User.DoesNotExist:
            raise InvalidToken('User not found.')
        
        # トークンを再発行する
        token = AccessToken.for_user(user)
        token['user_id'] = user.id
        token['is_staff'] = user.is_staff
        token['is_superuser'] = user.is_superuser

        data['access'] = str(token)
        return data
```

```CustomTokenObtainPairSerializer``` はアクセストークンの初回発行時に呼び出されるシリアライザで、```CustomTokenRefreshSerializer``` はトークンをリフレッシュの時に使います。

## カスタムビューの作成
続いて、カスタムビューを作成します。
と言っても、デフォルトのビューから利用するシリアライザを変更するだけです。
トークンの初回発行時とリフレッシュ時、それぞれで呼ばれるビューを定義します。

```backend/account/views.py```
```python
from rest_framework_simplejwt.views import TokenObtainPairView, TokenRefreshView
from .serializers import CustomTokenObtainPairSerializer, CustomTokenRefreshSerializer

class CustomTokenObtainPairView(TokenObtainPairView):
    serializer_class = CustomTokenObtainPairSerializer

class CustomTokenRefreshView(TokenRefreshView):
    serializer_class = CustomTokenRefreshSerializer
```

## ルーティングの追加
もともと、ルーティングには ```TokenObtainPairView``` と ```TokenRefreshView``` を登録していましたが、これを上記で新しく定義したカスタムビューに差し替えます。

```backend/app/urls.py```
```python
from accounts.views import (
    CustomTokenObtainPairView,
    CustomTokenRefreshView
)

urlpatterns = [
    ...
    path('api/token/', CustomTokenObtainPairView.as_view(), name='token_obtain_pair'),
    path('api/token/refresh', CustomTokenRefreshView.as_view(), name='token_refresh'),
]
```

## 動作確認
必要な実装は完了したので、動作確認を行います。
まずは、メールアドレスとパスワードを渡してトークンが発行されることを確かめます。

```bash
$ curl -X POST -H "Content-Type: application/json" -d '{"email": "admin@yukoweb.net", "password": "admin"}' http://localhost:8000/api/token/
{"refresh":"...","access":"..."}
```

アクセストークンとリフレッシュトークンが発行されることを確認できました。
アクセストークンを [JSON Web Token (JWT) Debugger](https://jwt.io) でデコードしてみると、確かに ```user_id``` や ```is_staff```、```is_superuser``` が組み込まれていることが分かります。

```json
{
  "token_type": "access",
  "exp": 1747580359,
  "iat": 1747573159,
  "jti": "6e7fb3b6f8c24f3a929bc2e631bfd1b0",
  "user_id": 1,
  "is_staff": true,
  "is_superuser": true
}
```

次に、リフレッシュトークンを使って JWT 認証を更新できるかを確認します。

```bash
$ curl -X POST -H "Content-Type: application/json" -d '{"refresh":"..."}' http://localhost:8000/api/token/refresh
{"access":"...","refresh":"..."}
```

リフレッシュトークンを JSON 形式で再発行用のエンドポイントにポストすると、新しくアクセストークンとリフレッシュトークンのペアが発行されます。
